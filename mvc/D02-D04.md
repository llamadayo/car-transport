# D02～D04 轉換與驗收

## 功能及路由

| 功能 | Controller／Service | 路由 | 宿主角色 |
|---|---|---|---|
| 單位主管審核 | CARGO_D02Controller／CARGO_D02Service | /CARGO_D02 | 單位主管 |
| 派車調度 | CARGO_D03Controller／CARGO_D03Service | /CARGO_D03 | 業務 |
| 運輸主管簽審 | CARGO_D04Controller／CARGO_D04Service | /CARGO_D04 | 運輸主管 |

沿用 Web／DTO／Service、Controller 直接 new Service、Dapper 參數化 SQL、Oracle 19c。共用流程在 Service，沒有 Repository。Controller 不繼承 CARGO_DController。Grid 使用 Html.Kendo().Grid；深藍側欄、橘色漸層、底線欄位、資訊卡與狀態徽章沿用既有樣式。

- D02：主管對應範圍查詢、明細、核准／退回（意見必填）、本頁待審批次核准。清單顯示簽核主管、自駕及貨物項數／總件數；待審顯示有效主管對應帳號，已審顯示實際簽核人。貨物合計使用 64 位元整數。
- D03：例行用車優先顯示、同時段優先提示、選車及雙司機、K／P 交集、座位／區間占用／保修／請假檢核；派車送簽、無車退回；派車生效後換車／換司機、展延、提前歸還确认／退回、自駕補派司機。
- D04：依申請單號／派車單號／申請人模糊查詢，可搭配日期與簽審狀態；同意／退回（意見必填）、本頁批次同意、歷次送簽與退回摘要。待簽審即保留資源；退回回到待調度並釋放指派。
- 批次針對按下按鈕時本頁可見待審單及其版本，1～100 筆；任何一筆失效則整批回復，重新查詢再送。
- 變更會增加版本及異動紀錄；通知只建待寄送紀錄，SENT_AT 為 null，不代表已寄信。

## 本機測試

沿用 `tools/Start-D01Demo.ps1`（名稱保留，現在同時啟動 D01～D04）。預設 http://localhost:5188/，從左側 D 模組進入三個角色功能。示範帳號刻意兼具三個工作角色，只存在既有 loopback 示範組態；公司組態仍要求宿主登入及角色。

1. D02 開啟 GU000002，核准後狀態為待調度。
2. D03 開啟同單，選「測試車 C」及「示範駕駛 C」，完成派車送簽。
3. D04 開啟同單，同意後成為待出車，通知欄顯示待寄送。
4. GU000007 可測運輸主管退回：意見必填，退回後到 D03 重新安排；簽審輪次保留。
5. GU000005 可在 D01 提出提前歸還，再到 D03 確認或退回；D03 也可測展延及換車。
6. 原始示範資料中車 A／司機 A 已生效，車 B／司機 B 待簽審，兩組均占用明日 09:00～17:00；車 C、D 與司機 C 可供測試。

網站重啟重置所有假資料。本機 UI 已驗證 D02 核准 → D03 送簽 → D04 同意，以及 D04 退回 → 回待調度；未連 Oracle 或寄信。

## 公司接入與尚待驗收

先審閱並在專用開發 Schema 執行 001_D01.sql、002_D01_sample_options.sql（僅測試選項）與 003_D02_D04.sql。尚未在 Oracle 執行，不可直接當正式部署腳本。003 沒有覆寫既有表格，也沒有搬移公司資料。

| 接點 | 草案與要求 |
|---|---|
| 主管關係 | CARGO_D_APPROVER：OWNER_ID 與 APPROVER_ID 對應 User.Identity.Name，ACTIVE=1；沒有對應則看不到 D02 申請。需改接公司核准者關係表。 |
| 角色 | 宿主提供「單位主管」「業務」「運輸主管」；若公司角色代碼不同，在 Controller 的 Authorize／Actor 及對應權限接入。不可只隱藏按鈕。 |
| 車輛／司機 | CARGO_D_RESOURCE：RESOURCE_ID 穩定唯一，KIND=VEHICLE／DRIVER、POOL=BIZ、ACTIVE=1；SITE 代表供補派判斷的當前據點，非僅行政歸屬。車輛提供座位與 K／P 證。 |
| 資源不可用區間 | CARGO_D_RESOURCE_BLOCK：維修、請假、C 模組占用均需公司資料接入；[FROM_AT, TO_AT) 半開區間。C 按日占用須轉成當日 00:00 至翌日 00:00，多日涵蓋末日整天；保修依原型按日，請假依既定排除期間。 |
| C/D 雙向共用 | 本次可讀取上述外部占用表，但未移植 C。未來 C 端也須讀 D 的完整 CARGO_D_ASSIGNMENT 區間（含待簽審），不能只看主檔目前車輛。尚不能聲稱已完成 C/D 實際整合。 |
| 簽審紀錄 | CARGO_D_SIGN 保存每輪摘要、結果、人員、時間；重新派車新增輪次。既有已派車資料若要搬入，需同步補齊簽審輪次與指派區間。 |
| 加班工時 | 畫面明確提示尚未接公司加班系統；不可用固定數字冒充即時剩餘工時。不據此擋派車。 |
| Email | CARGO_D_NOTICE 僅排隊紀錄，需接公司寄信路由及寄送結果回填；未寄出時 SENT_AT 為 null。 |

交易處理一筆／一批資料的一致性，VERSION_NO 防同一申請舊版本覆寫。依轉換規範不新增跨單容量鎖定／序列化策略；不同申請同時派相同資源仍存在檢查與寫入競態，公司需接受此限制或另行核定併發策略。清單在 Oracle 端篩選及分頁；明細／寫入目前載入工作資料快照，比對占用與交易版本，大量資料時須依實際資料量縮小查詢範圍並評估索引。

本機使用 MVC 5.3.0／Kendo 2026 驗證；公司 MVC 5.2.7／Kendo 2019 配套 DLL、JS、CSS 與 Oracle SQL／Unicode／交易均須公司環境再驗收。

## View 目錄調整（2026-10-10）

D02、D03、D04 各自使用 `Views/CARGO_D02`、`Views/CARGO_D03`、`Views/CARGO_D04` 下的 `Index.cshtml` 與 `Detail.cshtml`，Controller 採 `View(model)` 慣例尋找。各頁獨立定義查詢條件、Grid 欄位及操作；不再以 ViewBag.Module 切換主要畫面。原本 `Views/CARGO_D/WorkIndex.cshtml`、`WorkDetail.cshtml` 已移除。只共用 `Shared/_DApplication.cshtml` 與 `_DSignHistory.cshtml`，保留現有樣式、表單路由、AntiForgeryToken、版本欄位與 JavaScript 事件。ViewBag.Module 仍供既有 Layout 判斷標題使用。

## ViewModel 目錄調整（2026-10-10）

各功能的 ViewModel 分別放在 `ViewModels/CARGO_D02`、`ViewModels/CARGO_D03`、`ViewModels/CARGO_D04`，命名空間與資料夾一致，每個類別獨立使用同名檔案。例如 D02 包含 `CARGO_D02IndexViewModel`、`CARGO_D02RowViewModel`、`CARGO_D02DetailViewModel`、`CARGO_D02ActionViewModel`；D03、D04 依相同規則命名。D03 的車輛及司機選項另使用 `CARGO_D03ResourceViewModel`；D02、D04 的審核輸入不包含派車欄位。

真正共用的簽審歷程使用 `ViewModels/Shared/CARGO_DSignViewModel.cs`，`_DSignHistory` 僅接收歷程清單。唯讀申請內容沿用既有 `_DApplication` 與 `CARGO_D01DetailViewModel`。各功能分別由 `CARGO_D02Mapper`、`CARGO_D03Mapper`、`CARGO_D04Mapper` 轉換，重複的申請內容與簽審歷程轉換集中於 `CARGO_DSharedMapper`。原本 `CARGO_DWorkViewModels.cs` 與 `CARGO_DWorkMapper.cs` 已移除；Service 的共用 DTO 與業務規則維持原樣。

補派司機採逐筆獨立交易，依例行用車、用車起始排序；每筆重新讀取案件與資源狀態。單筆驗證、版本衝突或資料庫儲存失敗只回復該筆，保留其他成功結果並繼續處理。結果逐筆列出成功、失敗與略過原因，包含「用車時段已結束」。成功仍只建立待寄送通知紀錄，未串接 SMTP。

## D03 原型一致性（2026-10-11）
調度清單僅待調度例行單優先，再依用車起時排序。換車／換司機的可用資源依選定生效時間至結束重新查詢；伺服器送出時再驗證。僅換司機不重查原車資格；更換車輛仍檢查座位、K/P 與占用。展延只檢查新增區間的車輛／司機占用、保修與請假，不重查原車資格。
車輛 TONS 為噸位提示欄位；進入台北市且 TONS >= 6.5 才顯示個別警示，不作自動派車限制。新 Schema 使用更新後的 003；已建立的 Schema 另執行 005_D03_RESOURCE_TONS.sql（不要重複執行），由公司主檔提供噸位。未提供則顯示「噸位未提供」。SQL 尚未連 Oracle 執行。

D03 Detail 已補回資源表、派車判斷矩陣（標示本單）、即時結果預覽／送出阻擋、情境提示與單筆補派司機入口；申請資料與隨行貨物置於調度前。共用申請明細以 D03Section 分段呈現，其他頁仍維持完整輸出。補派入口保留原車並引導選司機及生效時間，沿用後端 reassign 驗證。加班工時明示未串接，通知維持待寄送。

## D01–D06 缺漏補齊與整合驗證（2026-10-11）

- D01／D02 待審明細顯示目前有效主管；已審案件保留實際審核人。清單補整單危險品，D01 另列運輸簽審及提前歸還待確認，D02 明細補危險品提示。
- D03 補派模式前後端均要求司機，允許同時換車；異動預覽及確認顯示前後資源。提前歸還顯示提出時間與原、新結束時間，清單補自駕及特殊需求。
- D04 清單待簽審優先，同組依最新送簽時間倒序；狀態、輪次、指派摘要及審核資訊均取最新簽審紀錄，退回後改判無車仍保留退回結果。
- 指派歷程補操作人、自駕及零長度不占用提示；換車、換司機、加派、補派在歷程及待寄送通知採具體類型。
- D05 修正單駕駛案件誤選第二司機，並保留清單關鍵字／狀態至明細、儲存及返回。D06 車輛標籤含識別碼及名稱，避免同名車混淆。
